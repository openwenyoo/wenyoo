# 校验、自动试玩与修改审查

在编辑器中打开 **文件 → Story quality · Validate / Auto-test / Changes**。
工具检查当前尚未保存的故事。修复问题后，关闭并重新打开面板即可检查新状态。

## 校验

校验检查模型字段、重复 ID、无效引用、角色位置、物品归属冲突、相互矛盾的等值条件、
缺失的定义，以及无法通过静态路径从起点到达的节点。使用 **Open** 跳转到对应的节点、
角色、物品或连接。

错误表示结构或引用有问题；警告需要作者判断。自然语言意图、Lua 和动态生成可能让玩家
到达静态图中不可达的节点。校验不能证明所有叙事逻辑都正确。

也可以不调用模型，直接运行相同的校验：

```bash
python scripts/validate_story_yaml.py stories/example.yaml
python scripts/validate_story_yaml.py stories/example.yaml --json
```

命令会解析 `includes`，拒绝 YAML 中重复的映射键；出现错误时退出码为 1，只有警告时不失败。

## 自动试玩

先修复校验错误，再设置玩家回合预算（1–30，默认 8），按需输入最多十条示例命令，
点击 **Run auto-test**。测试使用当前配置的 LLM，会消耗模型 token。每个玩家回合可能
包含多次 Architect 工具调用。

机器人以广度优先方式探索可用的预设动作和示例命令，每个选择使用独立的状态副本。
如果定义了可玩角色，会选择第一个。测试使用临时故事和临时存档，不加入正在运行的房间；
禁用延后生成和定时模拟。界面使用深度上限 4；启动及单回合各有 45 秒超时，整个请求最多三分钟。

报告包含命令、路径、叙事结果、已访问节点、结局、未访问节点、重复世界状态、运行错误，
以及没有可用动作的非结局节点。重复状态可能只是正常的观察动作。
需要表单回答或消歧回答的路径会提示人工测试。**Download report** 可导出 JSON。
测试覆盖是抽样的，不能保证所有自由输入、多人协作、定时逻辑或叙事质量都正确。

## 修改与版本历史

**Changes** 比较当前故事与载入编辑器时的版本。AI 编辑结束后会自动打开审查面板，
与这次编辑前的故事比较；AI 请求失败时也可以查看已经产生的部分修改。
节点、动作、实体、连接、参数等尽量按 ID 对齐；展开条目可查看修改前后的内容。

**文件 → 版本历史** 显示带 UUID、时间戳和摘要的不可变快照。点击 **Review changes**，
可与当前编辑内容或另一个快照比较。恢复前会先备份当前完整编辑内容，包括未保存修改。
保存也会为新内容创建快照。旧的编号版本仍然可读，并拥有稳定的 UUID。

快照位于 `saves/story_versions/<story_id>/`，包含 YAML 内容和 JSON 元数据。
新建的多文件故事快照会展开 includes，因此之后修改被包含文件不会改变快照内容。
仍包含 includes 的旧备份依赖原来的被包含文件。
